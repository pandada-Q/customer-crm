## 1. 收敛后需求概述

为一位不懂技术的小企业负责人（王总）建设一套「客户资料管理助手」：把首批多人多源多格式的客户资料（Excel / JSON / 微信文本 / 老系统导出，约 20 人级）规整为**一份统一、干净、带溯源、可直接使用**的客户数据，并部署一个**公网可访问的应用**持续承载：只读展示客户总表 + 待确认区拍板 + 合作意向客户识别 + 待办清单 + 新批次上传。

应用采用「**静态前端 + 轻量后端 + 数据库**」形态：上传新批次、冲突拍板、意向确认/驳回均即时入库生效、页面刷新即见，仅代码变更才重新部署；数据规模预期数百数量级，不做过度设计。应用设**单一访问口令**（凡持口令者均可查看与执行有限操作），本版不做登录鉴权与人级权限区分（列为后续版本规划）。

一期能力边界：
- **客户总表**：规整后全量联系人，支持搜索/筛选，总表含「来源」列（联系人级主来源），合作状态/标签可作筛选视图呈现意向客户；
- **待确认区**：承载三类待人工处理内容——跨源字段冲突（并列展示+推荐值，点选采纳推荐/用A值/用B值）、疑似重复、AI 低置信/未识别（原始片段+AI 候选值可空，人工对照补录或确认剔除）；全部修改留痕并可撤销；
- **合作意向客户**：AI 按「合作状态（有效=已合作/暂停=暂停合作/待定=有合作意向）+ 标签 + 备注语义」三类信号综合初判 → 进待确认区人工确认意向/驳回 → 确认后展示；
- **待办页**：从素材明确出现的非联系人事项抽离（如「张伟总监说下周约饭 记得提醒」），支持勾选完成，本版不做定时提醒推送；
- **上传入口**：任意格式投喂新批次，AI 抽取映射到既有 schema；不冲突直入（带来源标注），冲突/低置信进待确认区；
- **纠错渠道**：字段级更正走微信/电话告知受托方后台改库（主渠道），更正多时可打包「更正清单」投喂（可选路径），不做应用内纠错表单；
- **一页非技术说明**：交付物之一，客户不看代码也能放心使用。

数据侧口径：不做静默丢弃/合并；测试号与「待补充」占位行剔除留痕；公司名仅对可确证同一家的归一并留原写法、城市口语归一到地级市、tag 归一为枚举；溯源分「联系人级主来源」+「字段级冲突溯源」两层。跨源重复先按「姓名+公司」识别疑似同一人。

## 5. 明确排除项

- **登录鉴权与人级权限/角色区分**：本版只设单一访问口令，人级权限与登录鉴权列为后续版本规划（D18①）。
- **应用内自由增删改联系人及字段**：仅开放「冲突拍板、意向确认/驳回、待办勾选、上传新批次」有限操作；字段级编辑由受托方按批处理（D18③）。
- **应用内纠错反馈表单**（D20 排除 C）：纠错走微信/电话直达受托方（主）或「更正清单」投喂（可选）。
- **OCR / 图片扫描件处理**：本版不引入 OCR；本批扫描件_补充名单.jpg 损坏、不处理（D9）。
- **离线拍板 / 随数据更新重新部署**：已废弃，拍板走应用内待确认区、数据更新不触发部署（D15/D16）。
- **全量人工过目新批次**：不冲突直入，只对冲突/疑似重复/AI 低置信人工介入（D17）。
- **待办定时提醒推送**：本版只做勾选完成（D7）。
- **老系统持续对接/双向同步**：一次性迁移整理即可（D11）。
- **定量准确率验收门槛**：以提交物 5 项+清零待确认区为准，不设量化门槛（D12）。
- **数据静默丢弃/静默合并**：任何冲突、低置信内容均进待确认区人工处置（D3/D21）。
