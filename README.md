# 客户资料管理助手（Customer CRM Assistant）

一个**面向小型团队/个体的本地客户资料管理工具**：把散落在微信、表格、扫描件里的客户信息，用"确定性规则 + 大模型抽取"两条腿整理成一份结构化客户库，并对齐冲突、沉淀意向、跟踪待办。

> - **当前版本**：v0.1.0（见 [CHANGELOG](./CHANGELOG.md)）
> - **测试**：32/32 通过（`npm test`，零第三方依赖）
> - **运行方式**：单机本地部署，纯 Node.js（≥18）+ 静态前端，无框架、无数据库服务，JSON 文件持久化
> - **数据隐私**：所有数据仅保存在本地 `data/db.json`，不依赖任何外部数据库服务；未配置大模型 Key 时也不会联网

## 项目介绍

客户资料往往以多种形态散落各处：老系统的 CSV 导出、市场部手动维护的名单、微信聊天里随手发的联系人、甚至扫描件。人工整理面临三个老大难问题：

1. **重复**——同一客户在不同名单里出现多次，字段还不一致；
2. **脏数据**——手机号缺位、公司名里混进逗号、城市写成口语、标签重复；
3. **信息断裂**——谁有意向、谁待跟进、有哪些待办事项，散在沟通记录里没人管。

本工具把"整理客户资料"这条流水线产品化：**上传素材 → 自动清洗/抽取/合并/去重 → 需要人工判断的进"待确认区"拍板 → 沉淀为结构化客户库**，并提供总表管理、意向客户跟进、待办管理、上传留痕，以及一个**只查询系统内数据的 AI 问答小助手**。

AI 在本项目中的定位是"抽字段 + 答已入库数据"，**所有入库决策都可解释、可复核**：拿不准的进待确认区，绝不静默写入猜测值。

### 处理链路一览

```
上传素材(CSV/JSON/文本/微信记录)
   │
   ▼
确定性解析：CSV 错位智能对齐、引号还原、字段清洗、手机号位数校验
   │  .txt 自由文本：DeepSeek 抽取（无 Key 自动降级规则抽取）
   ▼
统一清洗规则(R1~R11，lib/rules.js)：城市口语归一、标签去重、合作状态三值化…
   │
   ▼
合并引擎：同人去重、无冲突自动合并、跨源冲突 → 待确认区人工拍板
   ▼
结构化客户库 + 意向初判 + 待办抽离 + 全程留痕(可撤销)
```

## 主要功能

| 模块 | 能力 |
| --- | --- |
| **客户总表** | 分页浏览、按姓名/公司/手机/城市/备注检索；城市/标签/合作状态筛选；编辑资料（dialog 表单）；冲突联系人默认隐藏、拍板后自动回归总表 |
| **上传入库** | 拖拽/多文件上传；CSV、JSON、TXT（口语文本）自适应；异步任务逐文件处理、进度渐进可见；自动分流：新联系人直入 / 同人无冲突合并 / 有冲突进待确认区 |
| **数据处理质量** | CSV 列错位智能对齐（公司名被逗号误拆自动还原）；手机号 11 位校验，短号**保留原值**并提示"位数不足"待人工补全（不静默丢弃）；非法邮箱/纯数字垃圾城市自动清理归位；**标签自动去重** |
| **待确认区** | 冲突（同人不同值）、合作意向初判、AI 低置信三类卡片，均带**来源文件**提示；采纳推荐/取值 A/B/人工修改补全；拍板即时生效并留痕、可撤销 |
| **意向客户** | 汇总已确认意向与合作状态=待定客户；列：电话/城市/合作状态/**跟进人**（含历史悬浮）/判断依据/来源；行内**跟进**（登记跟进人+时间）、**移除**操作 |
| **待办事项** | 素材中抽离的非联系人事项；状态机管理（待处理/完成/搁置/已移除）与带计数筛选；操作可逆、留痕可撤销 |
| **上传处理记录** | 上传卡片下方实时面板：每次上传每文件一条记录（时间/文件名/结果统计），可展开**处理明细**，失败也留痕 |
| **AI 数据小助手** | 右下角悬浮对话框；**只查询系统内数据**（客户/意向/待确认/待办/上传记录），DeepSeek 依据系统内快照给推荐；无 Key 自动降级本地关键词检索；首句引导防误解 |
| **审计留痕** | 全部修改/拍板/跟进/移除/上传记录可追溯、可一键撤销 |
| **测试工具** | "清空数据"按钮（仅 `DEV_TOOLS=1` 启动时显示），方便反复做上传测试 |

## 使用场景

- **市场/销售团队的客户资料初始化**：手里有几份老名单 + 一堆微信记录，一次性上传，自动清洗合并，冲突人工拍板，半小时得到一份可用的结构化客户库。
- **日常增量录入**：销售把新认识的客户随手发到群里/给到资料，格式随意——直接粘贴文本上传即可，由系统抽取入库，无需培训统一格式。
- **展会/活动后线索跟进**：上传扫来的名单，系统自动初判意向（"展会认识、可跟进"等信号），市场部在待确认区确认后到"意向客户"页跟进。
- **本地化、敏感行业使用**：客户资料不出本机（数据仅存本地文件），适合对数据外泄敏感的团队先跑起来。

## 技术栈与目录结构

- **后端**：Node.js 原生 `http` 模块（无框架、无第三方依赖），JSON 文件库 + 原子写
- **前端**：原生 HTML/CSS/JS（无构建步骤）
- **AI**：可选接入 DeepSeek（OpenAI 兼容 Chat API）；未配置时全功能可用（规则引擎）
- **测试**：Node 内置 `node:test`（同样零依赖）

    ├── run-firstbatch.js     # 一键用 input/ 样例重建演示库

    ├── .env.example          # 环境配置模板（复制为 .env 使用）
    ├── public/               # 静态前端 index.html / app.js / styles.css
    ├── lib/
    │   ├── store.js          # JSON 库 + 留痕/撤销底层

## 快速开始（干净机器复现）

下面步骤保证在一台**全新机器**（仅装有 Git 与 Node.js）上从零复现。全程零第三方依赖，**不需要 `npm install`**。

### 环境要求

| 依赖 | 要求 | 检查 |
| --- | --- | --- |
| Node.js | **≥ 18**（内置 `fetch`、`node:test`） | `node -v` |
| Git | 可选（用于克隆） | `git --version` |

### 第 1 步：获取代码

```bash
git clone <你的仓库地址> customer-crm
cd customer-crm
```

### 第 2 步：（可选）配置环境变量

```bash
cd 07-implementation
cp .env.example .env        # 然后用编辑器打开 .env
```

- **必改**：`CRM_PASSCODE` 建议改为你自己的口令（默认 `crm2026` 仅用于开箱演示）。
- **可选**：填入 `DEEPSEEK_API_KEY`（[DeepSeek 开放平台](https://platform.deepseek.com) 创建）。不填也能完整使用：结构化文件走确定性规则解析，`.txt` 自由文本走本地规则抽取，AI 小助手自动降级为本地关键词检索。
- 修改后需重启服务生效。

### 第 3 步：启动服务

```bash
node server.js          # 或 npm start
# [env] 已加载 .env：…
# 客户资料管理助手 已启动  http://localhost:4173  （口令见 .env / 默认 crm2026）
```

浏览器打开 <http://localhost:4173>，输入口令登录。

> **复现自检**：此时进入的是**空库**（无 db.json 时自动创建）。可先到"待办"页确认页面正常，即服务就绪。

### 第 4 步：灌入演示数据（二选一）

**方式 A — 页面上传（推荐，体验真实流程）**：在"客户总表"页右侧拖入 `input/` 下的样例文件：

- `客户名单-市场部.csv` / `客户名单-市场部 (副本).csv`：验证**同人去重**（正本+副本不重复入库）
- `合作伙伴名单(老系统导出).csv`：验证**跨源冲突进待确认区**（张伟手机号两值）
- `备份0812.csv`：验证 **CSV 列错位智能对齐**（秦岚公司名含误加逗号，自动还原为"深圳市创新科技有限公司"）
- `王总微信发来的.txt`：**自由文本**，验证 DeepSeek/规则抽取 + 意向初判 + 待办抽离
- `扫描件_补充名单.jpg`：演示图片被识别并跳过——文件可能已损坏，且当前 DeepSeek **文本模型不支持多模态/OCR**，无法读取图片内容（不影响其他文件处理）

**方式 B — 一键导入**（直接得到与集成测试同源的演示库）：

```bash
npm run import          # 读取 input/ 规整后写入 data/db.json
# 已导入过想重灌：npm run import -- --force
```

### 第 5 步：跑测试（可选，确认环境正确）

```bash
cd 07-implementation
npm test                # 32/32 通过：规整管线断言 + 应用 API 端到端 + 助手检索
```

> 测试会解析 `input/` 样例做断言，因此请勿增删 `input/` 内文件。

### 常见问题

| 现象 | 处理 |
| --- | --- |
| 页面打不开 / 端口被占 | 换端口启动：`PORT=8080 node server.js` |
| 忘记口令 | 在 `.env` 设 `CRM_PASSCODE` 后重启（或删除 `.env` 用默认 `crm2026`） |
| 想重置全部数据重新测试 | 停服，删 `data/db.json`（或换 `CRM_DB` 指向新路径），重启即空库 |
| 上传 .txt 没走大模型 | 检查 `.env` 是否已填 `DEEPSEEK_API_KEY` 且重启；未填则自动用规则抽取（功能不受影响） |
| 数据存在哪 / 如何备份 | 全部数据在 `data/db.json`，直接复制该文件即完整备份 |

## 数据处理规则（系统替你做的重要决定）

所有清洗决策集中维护在 `lib/rules.js`（R1–R11），并**注入 DeepSeek 抽取提示词**，保证"确定性规则"与"大模型抽取"遵循同一套口径。核心原则：**能确定的自动做，不能确定的绝不静默猜，进待确认区交给人**。要点：

- **去重**：同人（姓名/公司/手机任一强匹配）自动合并；标签集合去重；重复素材正本+副本不产生重复。
- **不丢原始信息**：手机号 10 位短号**保留入库**并提示"位数不足"待补全，而不是清空后笼统报"缺电话"；公司名内误加逗号按列类型智能还原。
- **归一化**：口语城市归地级市；合作状态归一为 `有效 / 待定 / 暂停` 三值（"展会认识、可跟进"→待定）；标签按枚举归一。
- **人工兜底**：跨源字段冲突、AI 低置信内容一律进待确认区，标注来源文件与推荐值，人工拍板后才生效，全程可撤销。

面向客户的通俗版解释见 [docs/客户使用指南-v0.1.md](./docs/客户使用指南-v0.1.md) 的"系统替你做的决定"一节。

## 安全与配置说明

> ⚠️ 本项目默认面向**本地/内网单机**使用，未内置多用户与强鉴权。公开部署前请务必阅读本节。

| 项 | 说明 |
| --- | --- |
| 访问口令 | 单一口令（默认 `crm2026`）保护页面与全部 API，通过 URL/Header 传参。**首次部署务必在 `.env` 修改** |
| 测试工具 | "清空数据"端点/按钮**默认关闭**（需 `DEV_TOOLS=1` 启动才开放），正式使用保持关闭 |
| 数据存储 | 客户数据仅存本地 `data/db.json`（该文件不入库、不入 Git）；备份即复制该文件 |
| 密钥 | `.env`（含 DeepSeek Key）已被 `.gitignore` 排除，勿强制提交 |
| 大模型数据边界 | 仅两类调用：① `.txt` 自由文本上传时把**文本内容**发给 DeepSeek 抽取；② AI 小助手把**系统内检索快照**发给 DeepSeek。配置 Key 前不会发生任何外呼 |
| 模型能力边界 | 当前接入 DeepSeek **纯文本模型**（`deepseek-chat`），**不支持多模态解析与 OCR**：图片/扫描件内容无法读取（示例 `扫描件_补充名单.jpg` 可能已损坏）。选型以控制成本为前提，**暂未引入 MCP 及任何第三方工具/视觉模型** |
| 样例素材 | 仓库内 `input/` 全部为**虚构演示数据**（姓名/电话/公司均为编造），不含真实个人信息 |

**环境变量一览**（详见 `07-implementation/.env.example`）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `CRM_PASSCODE` | `crm2026` | 访问口令（建议修改） |
| `PORT` | `4173` | 服务端口 |
| `DEEPSEEK_API_KEY` | 空 | 大模型抽取/问答（可选） |
| `LLM_PROVIDER` | 自动 | 大模型提供方（`deepseek`） |
| `DEEPSEEK_MODEL` / `DEEPSEEK_BASE_URL` | `deepseek-chat` / 官方地址 | 进阶自定义 |
| `DEV_TOOLS` | 关 | `=1` 时开放"清空数据"测试工具 |
| `CRM_DB` | `data/db.json` | 自定义数据库文件路径（测试隔离用） |
