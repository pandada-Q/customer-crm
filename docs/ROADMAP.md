# 版本规划（ROADMAP）

> 规划原则：**先安全、再体验、后自动化**。每个版本都收敛为一个"可独立交付、可验收"的增量；非紧急想法进 Backlog，不进当前里程碑。
>
> 版本号采用语义化：`主.次.修补`。当前 v0.1.0 已交付；下表从 v0.2.0 起为规划（未开工，按需调整）。

## 已交付

| 版本 | 主题 | 范围摘要 |
| --- | --- | --- |
| **v0.1.0** | 首个可交付闭环 | 上传自动整理（去重/清洗/冲突分流）+ 客户总表 + 待确认拍板 + 意向跟进 + 待办状态机 + 上传留痕 + AI 数据小助手 + 审计可撤销。见 [CHANGELOG](./CHANGELOG.md) |

## 规划中（按优先级排序）

### v0.2.0 —— 登录鉴权与访问控制
- **动机**：现状是单一口令 + "owner" 统一操作人（D18① 的权宜实现）。一旦多人使用，谁改了什么、谁能拍板冲突，都分不清，也存在口令共享风险。
- **范围**：
  - 多用户账号体系：账号/口令（BCrypt 或 scrypt 哈希存储，不再明文比较）；会话 Token（内存或签名 Cookie），退出即失效
  - 角色权限：`管理员`（全部操作 + 拍板 + 用户管理）与 `成员`（查看/上传/录入，拍板需管理员复核或按规则放行）
  - 审计升级：`operator` 从固定 "owner" 变为真实账号；留痕页可按人筛选
  - 口令策略：默认口令强制首次修改；`.env` 引导改为"首个管理员初始化"
- **关键验收**：未登录不可访问任何页面/API（除登录接口）；成员无法调用拍板/移除类写接口；留痕能区分到人。
- **依赖/备注**：涉及 server 鉴权中间层重构 + 前端登录态改造；数据无迁移（contacts/pending 结构不变，仅 operator 字段语义变化）。

### v0.3.0 —— 待办日期化与提醒
- **动机**：当前待办是"文字 + 状态"，"下周约饭""月底前回访"这类时间信息没有结构化，无法提醒。
- **范围**：
  - 待办增加 `dueDate`（精确到日期）+ `priority`；素材抽取时自动识别"约 X 日/下周/月底"等时间表达
  - 到期/逾期在待办页与总表角标红点提示；逾期自动标红排序
  - 行内快捷设日期；完成时自动记录完成时间（并回写关联联系人 followup）
- **关键验收**：上传含"下周三前回访李总"的素材，待办自动带出可识别日期；逾期待办有醒目提示。
- **依赖/备注**：需要扩展 ai.js prompt schema（todo 增加 dueDate）与规则手册；纯文本时间解析可先用启发式（"周几/几号/下周/月底"）再交给 LLM 兜底。

### v0.4.0 —— 定时总结与推送
- **动机**：数据每天在涨，但没有人每天主动打开看；希望系统"到点汇报"。
- **范围**：
  - 每日/每周总结模板：新增/合并/冲突待拍板数、意向客户、到期待办、上传记录统计
  - 推送通道：Webhook（企业微信机器人/钉钉/飞书）+ 邮件（SMTP 可选）；订阅配置存库
  - 可选：AI 生成一段"本周看点"（基于系统内统计，不越界外查）
- **关键验收**：配置每日 09:00 推送后，目标通道按时收到总结；推送失败有重试与日志。
- **依赖/备注**：v0.3 的 dueDate 是"到期待办"的前提；需要 Node 定时调度（`setInterval`/`node-cron` 或轻量自实现）；注意进程退出后补发逻辑。

### v0.5.0 —— 数据能力增强：Excel 导入导出 / 模板配置化 / 备份恢复
- **动机**：真实客户往往以 .xlsx 交付；导出也要能直接交给 Excel 用户；误操作后需要"页面内恢复"。
- **范围**：
  - Excel(.xlsx) 读取与导出（引入轻量解析依赖或调用系统能力）
  - 表头映射模板：用户可为自己的文件定义"第几列是什么字段"，模板可保存复用（回应"不同客户给的表头千奇百怪"）
  - 备份/恢复 UI：一键备份（存 data/backups）、列出历史备份、一键回滚；DB 版本号迁移机制（meta.version 已预留）
  - 导出字段可选（含跟进人/来源/上传时间），带脱敏导出（手机号中间打码）给外包/演示用
- **关键验收**：上传一份任意表头的 .xlsx 走自定义模板成功入库；误删数据后从备份页 2 步恢复。
- **依赖/备注**：目前"导出"仅 CSV（08-deliverables 曾用），xlsx 需新依赖；模板配置化建议先做"上传时字段映射修正"的轻量版。

### v0.6.0 —— AI 助手增强（只读 → 可控写）
- **动机**：v0.1 助手只做文本推荐；"点一下就能看/改"是自然的下一步，但**写操作必须留人工确认闸口**。
- **范围**：
  - 推荐结果可点：命中客户 → 跳转总表并自动带出该客户/筛选；命中待办/待确认 → 跳对应页
  - 问答记忆：同一次会话可追问（"第 3 个的公司在哪"）；对话上下文仅限系统内快照
  - 上传前"预检"：提交素材前先生成"将新增 N 条、合并 M 条、待确认 K 条"预览，用户确认后才真正写入（替代现在直接入库）
  - 明确**不开放**：助手直接改库/拍板（除非未来加"管理员确认"流程）
- **关键验收**：对话里点推荐客户跳到总表对应行；预检预览与实际结果一致。
- **依赖/备注**：需前端持有会话令牌做二次请求；跳转需各视图支持"定位到单条"。

### v0.7.0 —— 协同与交付形态
- **动机**：从"单机工具"走向"团队可用"，降低部署门槛。
- **范围（候选，按需裁剪）**：
  - 企业微信/飞书集成：把群聊里转发的联系人一键转成上传素材（自动拉取或机器人转发）
  - Docker Compose 一键部署（数据卷挂载 + 环境变量注入）
  - 只读访客链接（按部门隔离视图）——依赖 v0.2 角色模型
- **关键验收**：Docker 一条命令起服务并持久化数据；企微转发素材自动入库。
- **依赖/备注**：此项范围最大，建议拆子版本逐项推进。

## Backlog（未排期想法）

- 联系人合并的"自动采纳"策略可配置（当前一律人工拍板，未来可按规则自动采纳低风险冲突）
- 客户来源/录入人统计报表与简单仪表盘
- 多语言（当前仅中文界面）
- 移动端适配优化（当前桌面优先）
- 数据加密落盘（防本机文件被拷走直接读库）
- 冲突批量处理（同批次多条同类型冲突一键全采纳）

## 排序逻辑说明

1. **v0.2 安全第一**：不加账号体系，后续所有"多人协作/自动化推送"都缺地基（推送给谁、以谁身份操作）。
2. **v0.3 补齐数据结构**：dueDate 是提醒与总结（v0.4）的数据前提。
3. **v0.4 自动化尝鲜**：站在 v0.2/0.3 之上，验证"系统主动汇报"的价值。
4. **v0.5 数据能力**：真实业务从 Excel 来、要 Excel 去，且需要容错兜底。
5. **v0.6/0.7**：体验与生态增量，优先级可按客户反馈前移。

> 每个版本开工前，建议用本文档的"范围/关键验收"与需求方对齐一次，再进入任务拆解（拆解方法见 [docs/开发协作工作流.md](./开发协作工作流.md)）。
